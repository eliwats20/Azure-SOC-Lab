1. Initial Problem: No Logs Showing in Sentinel

This was the “setup hell” phase.

2. Fixing Azure Activity Logs
You discovered:

Azure Activity Logs have a cold start delay

They only ingest future events

They don’t backfill

The pipeline initializes only after a new event occurs

Deleting the stuck resource group via CLI cleared ghost metadata

Result:
AzureActivity table started populating correctly.

3. Fixing VM Security Logs (SecurityEvent Table)
You hit the next issue:

SecurityEvent showed data up to 3:12

Then queries returned no results

Then old data reappeared

But no new failed logins ever showed up

Ingestion looked “glitchy”

This indicated:

Root Cause:
AMA lost its Security channel subscription due to earlier DCR/diagnostic setting changes.

4. Identifying MDE Sensor Conflict
You found the service:

Code
sensrsvc
This confirmed:

Microsoft Defender for Endpoint (MDE) was installed

MDE was intercepting Security logs

AMA was extension-based, not service-based

AMA + MDE caused the Security channel to drop

This is a known Azure issue.

5. Fixing the Security Channel Subscription
You restarted the MDE sensor:

Code
Restart-Service sensrsvc
This forced:

MDE to re-hook into the event pipeline

AMA to re-sync with the DCR

Security audit channel to reinitialize

Backlogged logs to flush

SecurityEvent ingestion to resume

Result:
SecurityEvent table unfroze and began ingesting again.

6. Fixing Failed Login Visibility
You learned:

Failed logins generate Event ID 4625

They require proper audit policy

They require correct username/password attempts

They require the Security channel to be active

They do NOT require logging into the VM

Once the pipeline stabilized, failed logins began appearing.
